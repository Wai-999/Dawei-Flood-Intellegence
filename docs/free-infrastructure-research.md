# Zero-cost infrastructure investigation

Verified against current official documentation on 2026-10-03 UTC. Availability and quotas must be checked again in the owner's actual account immediately before provisioning. This document records technical selection, not provider account creation or a guarantee of capacity.

## Selection

**Persistent target: Oracle Cloud Always Free, one Linux VM and private Object Storage.** Prefer Ubuntu 24.04 on `VM.Standard.A1.Flex`, initially 2 OCPUs / 6 GB RAM / 50 GB boot volume. A free AMD E2.1.Micro is a capacity fallback if measured memory fits. Use only eligible home-region resources and verify aggregate existing account usage first. Do not upgrade, buy capacity, create a paid load balancer/NAT, or consume resources outside the free allowance.

Current Oracle documentation states **1,500 OCPU-hours and 9,000 GB-hours per month**, equivalent to 2 continuously running OCPUs and 12 GB RAM. This replaces the older 4 OCPU / 24 GB assumption. It also lists 200 GB combined boot/block storage, five volume backups, and 20 GB combined Object Storage with 50,000 requests per month. Capacity shortages and reclamation of sufficiently idle instances are real limitations. Do not generate artificial activity to evade reclamation. [Oracle Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

Owner signup can require phone and payment-card identity verification; the account owner must perform those steps and accept terms. The agent must never enter payment details or upgrade the account. [Oracle Free Tier](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier.htm).

**Executed fallback: one Railway anonymous VM, synthetic staging only.** An accountless SSH provision succeeded. The exact approved image ran behind Railway's trusted HTTPS proxy, with Caddy inside the VM enforcing proxy headers and application access controls. The 60-minute build window ends at **2026-10-03 07:48:50 UTC**. The preview is restricted to the creator's public IP. Unclaimed files are deleted; this is explicitly unsuitable for production SQLite or unattended operations. No account was claimed and no paid plan was purchased. [Railway anonymous VM](https://railway.com/free-vm).

## Capability assessment

For the viable Linux VM category (Oracle, Google Cloud and paid/credit VM alternatives), root access permits Docker, Docker Compose, Caddy and ordinary background workers. Single-host SQLite on **local ext4/xfs/btrfs** is the selected storage pattern; no NFS or shared network filesystem is used. IPv4/IPv6, firewall rules, public HTTP/HTTPS, outbound HTTPS to Telegram and Google, and object storage credentials must be verified in the actual account. These are architectural feasibility conclusions, not evidence that those services have been provisioned or contacted.

## Off-site destination alternatives

Oracle's private Object Storage allowance can be unlocked by the same account authorization as the VM. Backup content must be encrypted with an age public recipient before upload, and the identity retained off-host; the signing key also needs independent private escrow. Use least-privilege storage access and hard quota checks. Oracle storage in the same account is protection against VM loss, not independent-account disaster recovery.

Other current documented options are [Backblaze B2](https://www.backblaze.com/cloud-storage/pricing) (first 10 GB free; egress/transaction allowances apply; [signup](https://www.backblaze.com/sign-up/cloud-storage) advertises no card) and [Cloudflare R2](https://developers.cloudflare.com/r2/pricing/) (10 GB-month free allowance; request limits apply). Both require owner account/authorization. No unapproved operational data was uploaded to either or to GitHub.

The performed off-site drill used a **separate owner computer** receiving encrypted synthetic content from the cloud VM. This proves encryption/transport/decryption/signature/isolated restoration across hosts. It does not commission automatic production object backup, retention, on-call alarms, or measured operational RPO/RTO.
