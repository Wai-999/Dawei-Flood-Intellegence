# Keyless Sheets commissioning adapter

The dedicated private projection and prepared Editor identity are separate from the original source spreadsheet. Actual key creation was rejected by `constraints/iam.disableServiceAccountKeyCreation`; no key was produced and that policy remains intact. This is an architecture-solvable authentication boundary.

`infra/keyless-sheets.py` runs inside the exact approved application image, invokes its existing projection implementation and worker lock, and changes only the token provider. No application source or release image is replaced. Its private mode-0600 configuration contains the expected VM caller identity, separately scoped projection identity and dedicated Sheet ID. It accepts no embedded keys, configurable scopes or token endpoints.

The intended VM identity retains its existing private-backup bucket permissions. A resource-specific `iam.serviceAccounts.getAccessToken` grant on the projection identity and the additional `https://www.googleapis.com/auth/iam` VM access scope permit [short-lived credentials](https://docs.cloud.google.com/iam/docs/create-short-lived-credentials-direct). The projection identity receives no project role; the Sheet remains restricted. The adapter requests only the Sheets scope with a thirty-minute lifetime, validates the actual caller, refuses redirects and ambient proxies for credentials, and retains tokens only in memory. No owner OAuth credential or recovery identity is copied to the VM.

Before adding that IAM scope, metadata isolation must actually deny the app, backup and proxy containers access to workload metadata while allowing the designated Sheets container. `infra/metadata-isolation.py` adds owned Docker user-chain rules without flushing the existing firewall. Forwarded IPv6 metadata access is denied. A systemd dependency must reapply and validate the rules before the pilot starts after reboot. Rules configured on disk are not proof of actual access isolation; live allowed/denied requests are required. [Google's scope update procedure](https://docs.cloud.google.com/compute/docs/instances/change-service-account) requires stopping and restarting the existing VM; persistent data and its existing service identity must be preserved.

Projection requests are restricted to the dedicated Sheet and limited to ten reads and ten writes per minute per adapter process. The approved implementation still writes only `12_Dashboard_Export`, verifies its schema, uses RAW values, applies corrections and clears stale trailing owned rows. An idle worker records a technical heartbeat. Eight consecutive failures stop the adapter; the existing host recovery limit applies. Failures use fixed labels, with no exception payload, identity or token in logs.

[Current Sheets API limits](https://developers.google.com/workspace/sheets/api/limits) allow standard usage without additional cost, but describe planned charges for excess quota later in 2026. No quota increase or billing upgrade is authorized. These per-process controls are not a claim that all project/account usage was measured or that future pricing cannot change. The existing unupgraded trial guard remains active.

The adapter has configuration, scope/lifetime/cache/caller, redirect/endpoint, quota, bounded-failure/privacy and idle-heartbeat regressions. Live IAM, metadata isolation, read/write/readback, retry/correction/duplicate protection, restart, resource capacity and final header-only reconciliation must be tested before recording Sheets commissioning. Synthetic fixtures stay isolated from the operational database and are labeled explicitly; they cannot promote operational claims or provide field acceptance.

On the IPv6 pilot host, actual trusted Google API connections succeed over IPv6 while public IPv4 connections time out. `--ipv6` activates `provider_ipv6.py` for the three fixed provider hosts only. It requires AAAA resolution and refuses IPv4 fallback; it leaves link-local metadata and unrelated resolution unchanged. HTTPS hostname and CA verification remain in the original clients. `provider-launcher.py` applies the same transport to the approved integration module. Mount these infrastructure files read-only; do not alter the immutable application image or create public IPv4/NAT to work around address selection. Container reachability must still be tested per provider; host reachability alone is insufficient.

## Actual rollout

[Provider evidence](provider-commissioning.md) records actual narrow IAM authorization, scope stop/start, IPv4/IPv6 metadata requests before and after reboot, trusted IPv6 connections, real isolated write/readback/retry/duplicate/correction/removal and final header-only reconciliation. The active worker survived actual restart/recreation and automatic guarded host-reboot recovery. Complete field acceptance remains human-owned. No long-lived service-account key was created.
