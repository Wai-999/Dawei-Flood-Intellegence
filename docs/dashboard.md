# Dashboard information architecture and interactions

Desktop: fixed left navigation, source/sync context at top, persistent township/status/search/date filters, four primary indicators, reporting-by-township chart, investigation queue and location/report table. Record detail shows known values, missingness, observation time, severity contribution/interval, evidence status, freshness, source link and complete version history. Reviewer sees original cells/claims and approve/reject/reopen controls. Mobile: compact horizontal navigation and stacked cards, 44px inputs/buttons, horizontal tables, native form controls, visible keyboard focus and severity text alongside color.

Views: Overview; Situation map; Priority & investigation; Townships; Location register; Needs & coordination; Observation history; Statistics; Data quality; Verification; Reports & exports; System health; Method settings; Administration. Role gates hide actions as well as enforcing permissions server-side. Overview does not show invented people affected or a single unqualified ranking. Coverage text explains the incomplete inventory. The map is an interactive SVG Web Mercator view with reviewed supplied coordinates, clustering, zoom/pan/keyboard controls, field explanations and severity/confidence/freshness/investigation/confirmed-gap layers. It has no fabricated basemap/boundaries; the projection omits polar coordinates outside ±85.0511°. Unknown coordinates remain unplotted. Actual source geography is absent; browser GIS acceptance used a separate clearly synthetic fixture. Heatmap/choropleth and hazard layers require validated boundaries/exposure/denominators. Observation history groups latest permitted reports by observation day and is explicitly reporting activity, not a regional flood trend.

English/Burmese navigation is stored in a localization module. Source village names remain Unicode Burmese. Quantitative bars compare imported/reporting worklist counts, not inferred disaster severity. Filters persist across views and filtered exports. Loading/error/offline and last-calculated states are visible. No private API response is cached by a service worker. Device-local drafts retain the submission key across reloads, require deliberate save/retry and can be cleared. Correction drafts are bound to the report ID. PWA metadata is included; background sync/offline shell commissioning remains deferred.

Administration lists individual accounts and supports audited deactivation/revocation. Coordinator/reviewer can request owner follow-up from record detail. Method/priority detail exposes approved policy, missing contributions, field freshness and ordering sensitivity; analyst can retain an immutable calculation snapshot. Burmese navigation and core actions are centralized; some technical prose still needs local terminology review.
